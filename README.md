# Light Field Imaging Experiments (EE 5176 Computational Photography)

A small, readable, fully documented toolkit for experimenting with 4-D light
fields: the methods from lecture 15 (Ng et al. 2005, hand-held plenoptic
camera) and lecture 16 (Liang et al. 2008, programmable aperture), plus an
exploration of high-dynamic-range (HDR) light fields.  Everything runs on CPU
in NumPy/SciPy, has tests against a synthetic scene with known ground truth,
and is exposed through an interactive Streamlit app and Jupyter notebooks.

## Quick start

```bash
cd lightfield
python scripts/download_data.py          # ~1 GB: Stanford Lego Knights, Bracelet, one Lytro Illum ESLF
python -m pytest tests -q                # all methods verified on the synthetic scene
streamlit run app/streamlit_app.py       # interactive explorer (every method, sliders)
~/anaconda3/bin/jupyter lab notebooks/   # guided walk-through (use the anaconda jupyter: the /usr/bin one lacks ipywidgets)
```

```python
import lf
L = lf.io.load('lego', downsample=4, angular_crop=9)      # (9, 9, 256, 256, 3)
img = lf.refocus.refocus(L, alpha=-1.0)                    # focus on the castle wall
view = lf.aperture.synthesize_view(L, 2.5, 6.0)            # fractional viewpoint
d = lf.depth.depth_combined(L, alphas=np.linspace(-2, 1.5, 15))['disparity']
```

## Your own light fields

Choose **upload your own ...** in the app's dataset selector, or call
`lf.io.load_upload(bytes, filename)` / `lf.io.from_view_zip` / `lf.io.from_lenslet_image` / `lf.io.from_array`.

| File | Layout |
|---|---|
| `.zip` of views | one image per view: Stanford names `out_RR_CC_y_x.png`, any names ending in `row_col`, or a square number of files in row-major order |
| `.npy` / `.npz` | array of shape `(U, V, H, W)` or `(U, V, H, W, C)` |
| image (`.png`, `.jpg`, `.tif`) | lenslet / ESLF image: each micro-lens is a `U x V` pixel block (Stanford Lytro archive: 14 x 14) |

Uploads are decoded in memory (nothing is extracted to disk) with a 700 MB size guard.

## Deploying on Streamlit Community Cloud

1. Push this repository to GitHub (the datasets in `data/raw/` are not tracked).
2. On share.streamlit.io create an app from the repo with **Main file path** `app/streamlit_app.py`.
3. `requirements.txt` at the repo root is installed automatically; `.streamlit/config.toml` raises the upload limit to 400 MB.

The deployed app starts with the synthetic scene, a bundled real Lytro light field
(`lytro_people`), the upload option and the in-app downloader. Downloads on Streamlit Cloud land on the app's temporary disk, so they are
shared by all visitors and disappear when the app restarts.  The free
tier has about 1 GB of RAM, so use spatial downsample 4 and a 9 x 9 angular crop for
Stanford ZIPs.  `requirements-dev.txt` adds pytest and Jupyter for local work.

## Status and headline results

* `python -m pytest tests -q`: **86 tests pass** (library + Streamlit AppTest) in about a minute.
* 42 figures/animations in `docs/figures/`, regenerated from real data by `scripts/make_figures_*.py`.
* Refocusing: on Lego Knights (downsample 4, 9 x 9 views) the castle wall is sharp at
  α = -1.0, the knights at 0 and the near floor at +1.0; the usable ranges per
  dataset are stored in `lf.refocus.SUGGESTED_ALPHA_RANGE`.
* Depth: on the synthetic scene the defocus cue reaches MAE 0.002 disparity units
  (interior), the EPI structure tensor 0.03, correspondence 0.16; see docs/07.
* Multiplexing: the S-matrix gains (N+1)/(2 sqrt N) under read noise (1.51 at N = 7,
  2.07 at N = 15; theory and simulation agree to < 1 %) but is sqrt 2 *worse* than
  sequential capture under photon noise; slide 29's multiplexed row only holds if the
  programmable aperture's extra pixels are binned N:1 (docs/08, section 2.4).
* HDR light fields: per-view exposure bracketing with a checkerboard pattern and known
  depth reaches log-RMSE 0.49 in one shot versus 0.25 for full three-shot bracketing;
  refocusing must average linear radiance (clip-then-refocus log-RMSE 1.43 vs 0.16).

Known limitations: view synthesis is depth-free (ghosting at large disparities);
depth estimation is local (no global regularisation); the Lytro file is decoded from
the archive's pre-processed ESLF PNG, not from the camera's raw lenslet image; HDR
experiments are on a synthetic radiance scene plus pseudo-HDR on real data.
